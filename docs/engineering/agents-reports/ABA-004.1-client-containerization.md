**Status:** Complete
**Date:** 2026-07-24
**Commit:** None created

## Image Strategy

`client/Dockerfile` uses a two-stage image:

1. `node:22-alpine` installs the lockfile with `npm ci` and runs the Vite production build.
2. `nginxinc/nginx-unprivileged:1.28-alpine` serves only the generated `dist/` assets as the non-root `nginx` user on port 8080.

The final image contains no Node runtime, source dependencies, or local `node_modules`.

## Runtime and SPA Configuration

`client/nginx.conf` serves static assets from `/usr/share/nginx/html`, disables directory listings, caches immutable `/assets/` files, and falls back to `/index.html` for client-side routes. The image health check uses the runtime image's lightweight `wget` to request the local static root.

## Compose Changes

Added a `client` service without changing the existing `server` service configuration:

- Client: <http://localhost:3000>
- Backend health: <http://localhost:8080/health>

The client has no dependency or proxy relationship to the backend and continues using its mocked API boundary.

## Limitations

The client deliberately does not proxy to or call the Go backend yet. The static runtime is production-oriented for this assignment; TLS termination and external deployment configuration remain outside local Compose scope.
