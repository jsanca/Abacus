## Previous Design (ABA-006)

- `Expression` interface sealed with one unexported marker method `expressionNode()`.
- Evaluation performed by a centralized exported free function `Evaluate(expression Expression, operands []float64) bool`.
- Domain entry point was a free function `Validate(definition OperationDefinition, operands []float64) *ValidationDefinition`.
- Missing operands silently resolved to zero (e.g., `SecondOperand` with an empty slice returned `0`).
- `copyOperation` used `copy()` for the `ValidationDefinition` slice — shallow copy, leaving `AllOfExpression.Expressions` slice backing arrays shared.
- No startup validation of `ValidationDefinition` structure.

## Final Design (ABA-006.1)

### Expression evaluation ownership

`Expression` now carries a second unexported method `evaluate(operands []float64) (bool, error)`. Each concrete type owns its own evaluation logic:

- **`ComparisonExpression.evaluate`** — calls `resolveOperand` to get the value, applies its operator, returns an error for unsupported operator values. No silent zero fallback.
- **`AllOfExpression.evaluate`** — iterates children in declaration order, short-circuits on first failure, propagates child errors with index context.

The centralized `Evaluate` free function and the `Validate(definition, operands)` free function are removed. There is no competing public evaluation entry point.

### Operation-owned validation

```
operation.Validate(operands)
      ↓
ValidationDefinition.Expression.evaluate(operands)
      ↓
ComparisonExpression / AllOfExpression
```

`Operation.Validate(operands []float64) (*ValidationDefinition, error)` is the primary domain entry point. It iterates validations in declaration order, evaluates each expression, returns the first violated `ValidationDefinition` (nil on all-pass), or a contextual error identifying the operation ID, validation ID, and underlying cause.

### Malformed-expression behavior

- **Missing operand**: `resolveOperand` returns `ErrOperandOutOfBounds` with position and count context.
- **Unknown operand reference**: returns `ErrUnsupportedOperandReference`.
- **Unknown comparison operator**: `ComparisonExpression.evaluate` returns `ErrUnsupportedComparisonOperator`.
- **Nil expression**: `Operation.Validate` guards with an explicit nil check before calling `evaluate`, preventing a panic.
- **AllOf child error**: wrapped with child index context and propagated up.

All three sentinel errors (`ErrUnsupportedOperandReference`, `ErrOperandOutOfBounds`, `ErrUnsupportedComparisonOperator`) are package-level `var` values so callers can use `errors.Is`.

### Registry fail-fast validation

`validateRegistryOperation` now validates every `ValidationDefinition` before accepting an operation into the registry:

| Check | Error fragment |
|---|---|
| `ID` non-empty | `ID must not be empty` |
| `Message` non-empty | `message must not be empty` |
| `Expression` non-nil (via `validateExpressionDefinition`) | `expression must not be nil` |
| `OperandReference` known constant | `unsupported operand reference` |
| `OperandReference` compatible with operation arity | `requires arity` |
| `ComparisonOperator` supported | `unsupported comparison operator` |
| `AllOfExpression` children non-nil and recursively valid | `must not be nil` / recursive errors |

`validateExpressionDefinition` is unexported and recurses only over the two supported expression types, proportional to the closed hierarchy.

### Deep-copy strategy

**`copyExpression(Expression) Expression`** — added to `validation.go`:
- `ComparisonExpression` is a value type; copied by value.
- `AllOfExpression.Expressions` — a new slice is allocated and each child is recursively copied.
- Returns `nil` for a nil input (defensive, not reachable via registry-validated operations).

**`copyOperation`** — updated to use `copyExpression` per validation, replacing the shallow `copy()` call. Each `ValidationDefinition` is reconstructed with its expression deep-copied.

**`projectOperation`** — updated to call `copyExpression` when building `ManifestValidation`, isolating the manifest's expression tree from the registry's stored copy.

### JSON compatibility evidence

The `MarshalJSON` methods on `ComparisonExpression` and `AllOfExpression` are unchanged. `TestManifest_validationsSerializedCorrectly` verifies:

- Division: `{"kind":"comparison","operand":"second","operator":"notEqual","value":0}`
- Percentage: `{"kind":"allOf","expressions":[...]}` with 2 inner expressions
- Square root: one comparison validation
- Addition: empty `validations` array

`TestManifest_validationsDeterministicOrdering` confirms stable JSON across calls.
