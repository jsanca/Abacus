## Selected Recommendations

All recommendations endorsed for the `osk-go-guide` skill are drawn from the source. Summary:

- **Naming:** MixedCaps, lower-case packages (no plurals, no `util`/`common`/`lib`), `Err`/`err` error prefix, `Error` suffix for error types, descriptive names throughout.
- **Interfaces:** Defined by consumers; compile-time compliance checks; never pointer-to-interface; value vs. pointer receiver implications.
- **Pointers vs. Values:** Use pointers when mutability or large structs demand it; use values otherwise.
- **Maps and Slices:** Return nil (not empty slice) for empty results; check `len(s) == 0` (not `s == nil`); defensive copy at boundaries.
- **Mutexes:** Zero value valid (`var mu sync.Mutex`); never embed; named field only.
- **Errors:** Match type to need (`errors.New`, `fmt.Errorf`, custom type, sentinel var); wrap with `%w`; handle once (don't log-and-return); avoid `"failed to"` prefix.
- **Context:** First parameter; never stored in structs; propagated through call chain.
- **Goroutines:** Always stoppable and waitable; no goroutines in `init()`; `sync.WaitGroup` or done channel for lifecycle.
- **Defer:** Use for cleanup (locks, files); overhead negligible outside nanosecond-scale hot paths.
- **Testing:** Table-driven with `give`/`want` fields; `t.Run` for sub-tests; loop var capture with `t.Parallel()`.
- **Functional Options:** Only when 3+ optional parameters; interface-based preferred over closures.
- **Constructors:** `&T{}` over `new(T)`; named fields in struct initialization; `var v T` for zero-valued structs.
- **Globals:** Avoid package-level mutable state; dependency injection over global function pointers.
- **Embedding:** Do not embed types in public structs; never embed mutexes; embed only when the inner type's API genuinely belongs as part of the outer type's public API.
- **Line Length:** Soft limit of 99 characters (not hard-enforced).
- **Import Ordering:** stdlib group, blank line, external group.
- **Exit:** `os.Exit` / `log.Fatal` only in `main()`; prefer a single exit point via a `run()` function.
- **Enums:** Start at 1 with `iota + 1` unless zero is the desired default.
- **Time:** Use `time.Time` and `time.Duration` everywhere; no bare ints for time.
- **Formatting:** `goimports` for code formatting; `golangci-lint` as the lint runner.

## Recommendations Omitted

The following guidance from the source was not included in the skill:

| Topic | Reason for Omission |
|-------|---------------------|
| `go.uber.org/atomic` | stdlib `sync/atomic` is sufficient for small services; Go 1.19+ includes `atomic.Bool` etc. |
| `go.uber.org/goleak` | Extra dependency; goroutine lifecycle ownership rules suffice for small services. |
| Prefixing unexported globals with `_` | Uber-specific convention; conflicts with typical `_` discard meaning; avoids mutable globals entirely instead. |
| Full `revive` linter config | Covered by `golangci-lint` with sensible defaults; leave exact linter selection to project need. |
| Avoid `init()` as blanket rule | Listed as "prefer `init` alternatives first" rather than absolute ban; legitimate uses exist (regexp compilation, driver registration). |
| Channel size = 1 or none only | Included as guidance but not as dogmatic rule for all contexts. |
| Omit zero-value fields in structs | Explicit zero values can aid clarity in small projects; skill recommends judgment over rule. |

## Adaptations for Abacus

Several recommendations were sharpened or contextualized for the Abacus project's specific needs:

- **No speculative interfaces:** Emphasized more strongly given the project's function-based operation execution strategy.
- **Registry immutability:** Added specific guidance on immutable-after-startup registries (Abacus's concrete pattern).
- **Concurrent map reads:** Explicitly noted that concurrent reads of immutable maps require no mutex.
- **Function-based strategies:** Added preference for function types over class-like strategy hierarchies, reflecting Abacus's `ExecuteFunc` pattern.
- **`log/slog`:** Specified as the structured logging tool (per CLAUDE.md).
- **`httptest`:** Explicitly recommended for API-level tests (relevant to the Chi HTTP layer).
- **No-op telemetry:** Allowed as boundary implementation but must not become ornamental architecture.
